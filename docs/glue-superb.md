# Glue elemental SUPERB storage

GLUEBALL_MATELEM_COLORVEC and GLUEBALL_DIAG_MATELEM_COLORVEC now default to
native complex<double> SUPERB tensor output. Set Param/use_superb_format to false
only to request legacy SDB output. Use an explicit .sbt output filename.

Schema version 1 has vector-fastest ntdm axes: vector, time, normalized derivative
or displacement list index, and momentum. Metadata includes the tensor order,
operator convention (the measurement name), explicit displacement and momentum
dictionaries, eigenvalue weights, lattice, parameters, gauge metadata and producer
precision. The original formulas and normalization are unchanged. Whole vector/time
slabs are written with block checksums. Both variants use left=right=0 typed keys.

ADAT io/glueball_superb.h reads native tensors and legacy SDBs through the same
ColorVec DBGlueElementalOperator interface. It validates schema, axes, payload type
and dictionaries, and rejects missing/partial vector blocks and nonfinite values.
Rebuild ColorVec and relink Redstar after installing the new header.

The full 4³×16 derivative-glue storage comparison used ten double-precision vectors,
1,093 displacement choices and all seven momenta with p²≤1: all 122,416 keys and
1,224,160 complex values were finite and matched the legacy output exactly.
Invalid left index, missing displacement/momentum and out-of-range time were
rejected. The DIAG variant is compiled; its runtime storage test is tracked
separately. Chroma validation uses an incremental pre-YLM baseline rebuild,
not a clean build of the latest YLM checkout. No legacy dataset was overwritten.

The user-authorized retained gpdf_2_0.00.sdb is a separate legacy gluonic insertion
input; it is not regenerated by these glue elemental tasks or claimed as fresh
64-bit data. no_1pt remains experimental; corr_graph.bin is unchanged.

Without BUILD_SB, the measurements retain legacy output by default and reject an
explicit request for SUPERB output. Both configurations compile.
